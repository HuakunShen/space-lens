## Core Decision/Topic

Follow-up on the unified Memory view: process rows needed a right-click
surface, state at a glance, a working sort, and an answer to "what did an
editor/AI leave running?". The first cut also exposed two real bugs: the
hover-freeze made every column sort look inert, and sysinfo's macOS argv
parser could append environment variables to a command line when a process
used `setproctitle`.

## Options Considered

**Right-click menu**
- *Native NSMenu* — better platform feel, but the table is a web surface and a
  native menu would need a new host arm for every action.
- **shadcn-svelte ContextMenu (bits-ui) chosen** — already a workspace
  primitive, keyboard reachable, and keeps the actions in the same place on
  macOS/Windows/Linux and in the browser. One menu per virtual row; content is
  portalled and only one menu is open at a time.

**Sorting**
- *Remove the order-freeze* — fixes sorting but reintroduces row teleporting
  while the pointer rests on the table.
- **Unfreeze on an explicit sort (chosen)** — a header click is an instruction;
  the freeze still protects passive hovering and keyboard focus.

**Stale detection**
- *Flag every orphan/long-idle process* — the first run produced 43 rows:
  a wall of idle zsh sessions, a menu-bar broker, and simulator helpers.
- **High-precision runtime rules (chosen)** — zombie/stopped always; known
  runtimes (node, bun, python, java, …) orphaned for 30 min at low CPU or idle
  for 2 h; orphaned port listeners without a runtime at 30 min. Interactive
  shells are excluded. A port is context, never the only reason. Nothing is
  auto-quit.
- *Lazy detail endpoint for ports* — not needed: `lsof` is ~60 ms and its
  pid → listening-port map is cached for 10 s.

## Key Changes Made

- `ProcessTable` — per-row shadcn context menu (Inspect, Add to Quit list,
  Quit, Force quit, Copy PID/name/command/path/listening ports), a footer copy
  confirmation, state dots in the name cell and State column, and the sort
  unfreeze. `onQuit`/`onForceQuit` are only supplied when process control is
  available.
- `ProcessStateDot` + state tones in `labels.ts`.
- The table gained a dedicated **Ports** column (union of the group's member ports; up to two
  fit, longer lists show the first plus `+n`), a **Ports** filter, and port-number search. Hovering
  the Ports cell opens a shadcn-svelte HoverCard (bits-ui `LinkPreview`) listing every port. The earlier `:port`
  badge in the name cell was removed once the column existed: a labelled column is clearer than
  a colon-prefixed number.
- `lib/memory/stale.ts` + `memory-stale.test.ts`: pure heuristic, typed reasons,
  score, thresholds; excludes shells, apps, system components, other users and
  protected processes.
- `StaleProcessesPanel` and a fourth Memory sidebar section (Stale) with a
  badge and an Overview callout.
- `crates/memory/src/platform/ports.rs`: `lsof -nP -iTCP -sTCP:LISTEN -Fpcn`,
  parsed and cached for 10 s; `ProcessRow.listeningPorts` on the wire; the
  dialog and stale panel show the ports. macOS-only for now; other platforms
  report an empty list.
- Fixed macOS command leakage: `command_line_from_args` stops at the first
  `NAME=value` token, because sysinfo fills empty argv slots from the
  environment after `setproctitle` (Raycast Backend was the live example).
  Tests cover both the stop and its narrow detection.
- `runningSecondsFromIso` treats the Unix epoch as unknown, so groups whose
  members have no readable start time no longer say "20749d".

## Future Considerations

- Ports are macOS-only (`lsof`). Linux could use `/proc/net/tcp` + fd inode
  mapping; Windows would need `GetExtendedTcpTable`.
- The stale rules are heuristics and will need tuning from real user reports.
  A future "Review all long-running" filter could cover the non-runtime,
  no-port cases without lowering precision.
- Context-menu copies have no toast yet; the footer confirmation is the
  lightweight version.
