# 2026-09-26 14:34 +08 — Space Lens Xross view entry

## Core decision

Add a distinct native-backed Xross view while retaining Space Lens's standalone HTTP and Tauri workbench. This is Plan 0083 Task 2; it is a peer UI consuming Xross's portable Task 0.4 contract, not a native target implementation.

## Options considered

- Reuse the path-authoritative `WorkbenchService` and send paths from the WebView. Rejected: the remote target owns root and node authorization, and target-authored display paths cannot become operation handles.
- Treat `xroot_` as `xnode_` to open a ready scan. Rejected after the contract audit: the ID domains are intentionally distinct. Xross added a reviewed ready-only `rootNodes` binding; the adapter validates the full root set and chooses the selected root's node by ID, independent of row order.
- Package the Xross route through SvelteKit's ordinary static build. Rejected after inspecting the local artifact: it bundled the legacy HTTP/Tauri route and produced a service worker. The dedicated Vite entry mounts the same Xross component and shared 2D presentation, with separate local and hosted outputs.
- Trust `displayPath` as the breadcrumb/chart path. Rejected after a fake host supplied `/Users/private/...`: the peer display reconstructs root-relative paths from the approved root label and node names. Target paths remain display-only and are never sent back.
- Ask for cleanup/iCloud confirmation with `window.confirm`. Rejected: the WebView can only preview a target plan and call Xross's native approval method with an opaque plan ID. Native remains the authority for any execution.

## Final decision and rationale

The Xross adapter is separate from standalone transports, checks the full view context around calls, bounds tree/cursor work, reconciles scan gaps with `getScan`, and fails closed on malformed ready root bindings. Shared chart/list/breadcrumb/collector components keep the accepted 2D interaction, with five locale catalogs and host-selected locale. Local and hosted packs have their own static entry; standalone web/Tauri builds keep their existing entry.
