# 2026-06-15 22:29

## Core Decision/Topic

Implemented the first full Space Lens web GUI path and moved the frontend/backend boundary to a typed `SpaceLensAPI` over KKRPC WebSocket for standalone NPX mode.

## Options Considered

- Keep hand-written REST/fetch endpoints under `/api/*`.
- Use Hono RPC client typing over the existing REST-shaped API.
- Use KKRPC as the canonical app protocol, with Hono only hosting static assets and the WebSocket upgrade.

## Final Decision & Rationale

Use KKRPC as the canonical protocol for app calls. Hono remains the Node-compatible static and WebSocket host, with `/rpc` exposing `SpaceLensAPI`.

This keeps the frontend type-safe without tying app logic to HTTP route shapes. It also leaves the right future path for Kunkun: plugin mode can expose the same `SpaceLensAPI` through a different KKRPC transport, such as stdio or Kunkun IPC, while page and component code continue to call the same client abstraction.

REST-style `/api/*` routes remain only as compatibility/debug wrappers around the same backend service.
