# 2026-09-25 01:05

## Core Decision/Topic

Publishing auth for `dsh-plugin-spacelens` moves to npm **trusted publishing
(OIDC)** — no `NPM_TOKEN` secret, ever. The user published 0.1.0 by hand
(interactively, with 2FA available) and wants every later release to be a tag
push that CI publishes with a public `--provenance` attestation.

The deciding fact: npm's trusted publishing matches the workflow's OIDC claim
against per-package "Trusted Publisher" settings, so the secret the old
workflow required is simply gone — the thing to configure instead is the
connection on npmjs.com (`HuakunShen/space-lens`, `dsh-plugin.yml`, environment
`npm`, "Allow npm publish" checked, since the workflow publishes directly
rather than via `npm stage`).

## Key Changes Made

- `.github/workflows/dsh-plugin.yml` — `permissions: id-token: write`, publish
  step upgrades npm (>= 11.5.1 for tokenless trusted publishing) and runs
  `npm publish --access public --provenance`; header comment rewritten.
- `package.json` — `apps/dsh` registered in the root workspaces. It had been
  missed when the directory moved from `integrations/`, so `npm publish`'s
  `prepublishOnly` (`yarn build` from inside the package) failed yarn's
  workspace check. This also re-references the `space-lens@npm:0.2.8` entries
  that keep the lockfile honest.
- `CI.yml` / `npm-cli.yml` — every `yarn install` that runs **after
  `prepare-ci-install.mjs strip`** is now `--no-immutable`. Yarn 4 defaults to
  immutable installs in CI, but strip deletes `packages/node`'s
  optionalDependencies on purpose; the tree diverges from the lockfile by
  design. This never bit before the engine-submodule merge because the npm
  `space-lens@0.2.8` package used to keep the platform entries referenced —
  but the merge bumped the workspace to 0.2.8 too, so `^0.2.x` now resolves to
  the workspace and strip is what holds those entries.
- `packages/node/package.json` — `bin` restored to object form
  `{ "space-lens": "bin/cli.mjs" }`. The merge flattened it to a bare string
  (npm-equivalent for an unscoped package, but wrong vs the published 0.2.8
  metadata and vs `package-cli.spec.ts`, which failed on all 16 CI
  platform/node combos because of it).
- `workbench.yml` desktop-test — stubs `apps/web/build-desktop` before
  `cargo test`: `tauri::generate_context!` panics at compile time when the
  gitignored `frontendDist` is absent. macOS/Ubuntu went green; the Windows
  failure turned out to be a different bug.
- `apps/desktop/src-tauri/tests/engine.rs` — `refuses_paths_outside_roots`
  scanned `/usr`, which is not an absolute path on Windows; the temp dir (the
  fixture root's parent) is outside the roots and exists on every platform.

## Non-Goals

- Did not touch the open version-line question (engine `v*` vs plugin
  `plugin-v*` vs desktop `app-v*`); today's fixes keep the three lines as they

  for dev builds — bumping the workspace past 0.3.0 would silently re-point
  apps/dsh at the npm package.
