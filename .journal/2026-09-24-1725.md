# 2026-09-24 17:25

## Core Decision/Topic

Three collector/picker UX gaps closed, all reported from actually using the app:
(1) the Choose Folder card demanded a hand-typed absolute path although the
desktop already had an unused native dialog command; (2) `~/Dev/...` was refused
while only full absolute paths worked; (3) collector membership had no visible
toggle — plus collected, but the only removal path lived inside the Collector
panel, and right-click silently collected instead of offering a choice.

## Options Considered

**Where `~` expands:**
- *Per client* — the browser does not know the user's home, so it cannot.
- **Server-side in `ScanManager.containRoot` (chosen)** — every frontend (browser,
  embed, DSH panel) types paths against the same local machine `spacelens serve`
  runs on; the server is the one place home is known for all of them. The desktop
  additionally expands in the page (home via Tauri ports) since its engine path
  is the Rust FFI, not this store.

**Folder picker per environment** (the product runs on many ends):
- *Port Refyard's browse dialog* (host-side directory listing) — right for SSH
  targets, but Space Lens has no remote targets yet, and it would mean a new
  contract endpoint expanding the server's filesystem surface for little gain.
- *Browser `showDirectoryPicker`* — useless here: browsers never expose the
  absolute path, which is what the scan contract needs.
- **Native dialog on desktop (chosen)** — `sl_host_request`/`PickDirectory`
  already existed in Rust but nothing called it. The affordance is gated by the
  capabilities flag `host.folderPicker` (refyard's pattern: the flag, not the
  callback's presence, decides whether the button exists). Browser keeps manual
  entry, honestly labelled by the button's absence.

**Collector toggle:** one verb per row state — the row button flips Plus → Minus,
and a bits-ui ContextMenu (first of the shadcn set in this repo, hand-written to
match the existing wrappers) offers Move to/Remove from Collector plus Open.
Right-click on the sunburst chart now toggles membership too.

## Key Changes Made

- `apps/desktop/src-tauri/src/commands.rs` — `sl_host_request` rewritten onto the
  Channel reply pattern every other command uses (the invoke body is unreliable
  on macOS); the pick runs in `spawn_blocking`, never the main thread.
- `packages/client` — `WorkbenchService.pickFolder?` (optional; HTTP adapter
  simply has none), `TauriPorts.homeDir?`; `tauri-ports.ts` sources it from
  `@tauri-apps/api/path`.
- `packages/host` — `containRoot` expands a leading `~` against the process
  home; regression test covers `~/…` resolving into a root and bare `~` still
  refused (host suite 44/44).
- `packages/web-ui` — new `ui/context-menu` (Root/Trigger/Content/Item over
  bits-ui v2's `child` snippet, not `asChild` — that cost one broken build to
  learn); `ChildList` toggle + menu; `ScanPicker` gains `folderPicker`,
  `onPickFolder`, `chromeInset` (header inset rule aligned with the page
  header's: macOS 88px, Windows right-side 152px).
- `apps/web` — page wires capabilities → picker button, expands `~` desktop-side,
  passes `uncollect` into the list.

## Verification

svelte-check (web, web-ui, client) and contract/host typechecks all clean; host
tests 44/44; `build:desktop` and `yarn build:dsh` build. Live through the DSH
panel with headless Chromium: plus adds, minus removes, right-click shows the
styled menu ("Move apps to Collector" / "Open apps"), menu Open navigates, and
no Browse button renders where the capability is false. Not verified: the real
Tauri dialog on either OS (needs a full bundle build).

## Future Considerations

- A Refyard-style host-side browse picker becomes worth porting when Space Lens
  grows remote (SSH) targets or a hosted UI where the server browses on behalf
  of a remote browser — it needs a filesystem-listing contract endpoint first.
- `~` expansion is server-side only for HTTP clients; the desktop page expands
  before submit. If a third engine appears, consider moving expansion into the
  contract documentation explicitly.
