## Core Decision/Topic

The Storage and Memory views had drifted into two different shells. Storage
had a draggable macOS toolbar (`LensToolbar`), a sidebar, and Settings; Memory
had its own 40 px header row with neither drag region nor Settings, plus a
single long scroll. The Memory process view also stopped at name/CPU/memory:
no start time, duration, owner, state or command line, while neohtop treats
those as first-class process data.

## Options Considered

**How to unify the shells**
- *Keep the Memory header and add a drag region + gear button* — smallest
  patch, but the two views keep different title heights, different sidebar
  behavior, and a second place to maintain the switch.
- **Mount Memory inside the Storage shell (chosen)** — `LensToolbar` is the
  title bar in both views, `MemorySidebar` replaces scan locations with the
  three Memory sections, and `AppearancePanel` stays a single global Settings
  sheet. The fixed **Storage | Memory** pill now renders for both views, so the
  switch never moves when the view changes.

**What to put in the Memory sidebar**
- *Nothing / copy the storage locations* — locations are meaningless here, so
  the first is a regression and the second is confusion.
- **Sections + one live reading (chosen)** — Overview, Processes, Activity, and
  a "Now" card (used %, pressure, sample time). The card keeps system context
  visible while the user is in a process-focused section.

**How to expose process detail**
- *Always send argv in every snapshot* — simple, but it inflates the 1 Hz wire
  frame and exposes command lines the user never asked to see.
- **Send the detail fields with the snapshot, but gate the command line on
  ownership (chosen)** — one wire type, no second endpoint; the extra 1 Hz cost
  is measured and budgeted. `ProcessRow.command/user/state/threads` are small
  scalars; the full "neohtop" presentation lives in a drawer that is opened on
  demand.
- *A lazy per-process details endpoint* — best bandwidth story, but it needs a
  new IPC arm in every host and a live identity recheck for a read-only view;
  deferred.

**What to take from neohtop**
Neohtop shows PID, name, status, user, CPU, RAM, VIRT, disk I/O, parent PID,
root, command, environment, session id, start time and run time; its detail
modal adds child processes. Space Lens took the memory-relevant half: command,
start time, running duration, owner, state, thread count, parent and children.
Environment variables, working/root directories, session ids and disk I/O stay
out (privacy and out of scope for a memory view).

## Key Changes Made

- `apps/web/src/routes/+page.svelte` — Memory renders through the same
  `workbench-shell` / `LensToolbar` / `workspace-body` shape as Storage;
  toolbar Settings and sidebar toggle work; the Storage | Memory pill is shared;
  section state persists in `localStorage['spacelens.memory.section']`.
- `packages/web-ui/src/components/memory/MemorySidebar.svelte` — section
  navigation plus the live used/pressure card.
- `apps/web/src/lib/memory/MemoryPage.svelte` — renders Overview / Processes /
  Activity; Overview gains a top-six "Top memory users" list; the page owns the
  new process-detail selection (identity, not a stale row).
- `packages/web-ui/src/components/memory/ProcessDetailDialog.svelte` — a
  shadcn/bits-ui dialog matching neohtop's modal shape: header stats, a
  full-width command card with Copy, then process information, resource usage,
  timeline, walkable children and single-process quit actions.
- `ProcessTable` — Running column default on; Details toggles Started / User /
  State / Command; search extends to command, account, state and bundle path;
  process rows open the detail drawer instead of the group drawer.
- `ProcessDrawer` — groups show running time and member rows open the process
  detail.
- `crates/memory` — `ProcessRow` gains `command`, `user`, `state`, `threads`;
  `RawProcess` carries them; the portable sampler refreshes `cmd`, tasks and
  users; macOS reads `proc_taskinfo.pti_threadnum` (sysinfo has no macOS
  `tasks()`); `build_groups` nulls argv for processes owned by another account.
- Contract `1.1.0`; the 1000-row wire budget moved from 250 KB to 400 KB with
  a representative command on every row.

## Future Considerations

- Command lines are still sampled on every tick for owned processes. If the
  1 Hz frame becomes a problem on machines with thousands of processes, move
  command/path to a lazily requested detail arm and keep only `state/user` in
  the snapshot.
- The "Activity" section is a single collapsed audit log; once there are more
  audit records it may deserve a real timeline layout.
- Disk I/O and environment variables from neohtop are deliberately not
  implemented.
