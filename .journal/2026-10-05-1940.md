# 2026-10-05 19:40 (Asia/Singapore)

## Core Decision/Topic

Implement substantive native interface styles in `feat/interface-styles` after
user review of generated macOS, Windows WinUI and Linux GNOME concepts.

## Options Considered

Extend global CSS overrides, fork entire platform UIs, or use native Tailwind
variants in the existing shared components. The previous global treatment
mostly changed materials and selection colors and missed startup controls.

## Final Decision & Rationale

Keep behavior and Bits UI accessibility shared; move geometry, density and
hierarchy into component-level Tailwind variants. Reserve CSS for semantic
colors, fonts, materials and base layout. Choose GNOME/libadwaita as the Linux
visual reference. Native caption controls remain supplied by Tauri/the OS.

## Key Changes Made

- Startup reuses the workspace navigation and toolbar, with macOS horizontal
  form labels and WinUI/GNOME grouped surfaces.
- macOS compact source lists and file/folder row icons; WinUI page heading and
  command actions; GNOME centered title and larger raised header controls.
- Platform-specific Button, Input, Checkbox, Select, menus and sheet surfaces.
- Linux preference persistence and automatic desktop detection; browsers and
  Android retain Web defaults. Density remains separately selectable.
- Remove old platform CSS selector overrides, layer base theme/layout CSS below
  utilities, and fix native graph sizing and contents-only layout regressions.

## Verification

Linux detection/persistence tests were observed failing before implementation,
then passing. Web and web-ui unit suites and Svelte diagnostics were run.
Browser verification uses a disposable local scanner fixture and checks native
style/theme switching, startup paths, scan, selection, menus, narrow-window
charts and full-width contents-only layouts. Screenshots capture rendered UI.
Build logs retain the existing client static/dynamic-import optimization warning.

## Future Considerations

Browser previews on macOS exercise all style variants, not actual Windows/Linux
window managers or their platform font rendering. Verify those native hosts when
available. Keep new platform geometry on components, and preserve responsive
conditions when overriding base layout in the utilities layer.
